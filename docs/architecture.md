# Architecture

## Overview

This lab implements a small Google Cloud environment designed to demonstrate practical infrastructure administration using low-cost resources.

```text
                         INTERNET
                            |
                            | HTTP :80
                            v
                  +--------------------+
                  |   Compute Engine   |
                  |   cloud-lab-vm     |
                  |     e2-micro       |
                  |  Ubuntu 24.04 LTS  |
                  |       Nginx        |
                  +---------+----------+
                            |
              +-------------+-------------+
              |             |             |
              v             v             v
       cloud-lab-vpc   Cloud Logging   Cloud Monitoring
       10.10.10.0/24                       + Alerting
              |
              v
      cloud-lab-backup
       Service Account
              |
              v
        Cloud Storage
          Backups
```

## Network

- VPC: `cloud-lab-vpc`
- Subnet: `cloud-lab-subnet`
- CIDR: `10.10.10.0/24`
- Region: `us-central1`
- Zone: `us-central1-a`

The VPC uses custom subnet mode to avoid relying on the default Google Cloud network.

## Compute

The workload runs on a Compute Engine VM:

- Name: `cloud-lab-vm`
- Machine type: `e2-micro`
- OS: Ubuntu 24.04 LTS
- Web server: Nginx

The instance receives a private address from `10.10.10.0/24` and a public address for lab HTTP access.

## Firewall

Two ingress rules were configured for the lab:

- TCP/80 for HTTP
- TCP/22 for SSH administration

Both rules use the network tag `cloud-lab`.

For production, SSH should not remain broadly exposed. IAP/OS Login, source IP restrictions, bastion patterns, or other secure administrative access controls should be considered.

## Identity and access

Backup operations use the dedicated Service Account:

`cloud-lab-backup@gcp-cloud-infrastructure-lab.iam.gserviceaccount.com`

The VM is associated with this identity and uses IAM permissions to access the Cloud Storage bucket.

## Storage

The Cloud Storage bucket is used as the backup destination for Nginx configuration and website content.

Backup source paths:

- `/etc/nginx`
- `/var/www/html`

The backup archive is uploaded under:

`backups/`

## Observability

Cloud Monitoring is used for VM metrics such as CPU, network, disk activity and uptime.

Cloud Logging is used to inspect infrastructure logs generated by the VM and Google Cloud services.

## Cost-conscious design

The initial version intentionally avoids higher-cost components such as GKE, Cloud NAT, Cloud SQL and external load balancing. These are planned for later versions when the architecture is expanded.
